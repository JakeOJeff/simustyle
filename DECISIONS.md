# Technical decisions

- 2026-10-10: Scene settings are fully populated in memory and default values are omitted from saved JSON; loading fills defaults back in.
- 2026-10-10: Component updates merge field patches, while `null` removes a whole component; inverse batches capture the smallest restorable values.
- 2026-10-10: A batch validates against its final candidate scene and commits atomically, allowing related components to be created together.
- 2026-10-10: Animator `tracks` are registry-managed timeline data and stay out of the ordinary schema-driven inspector fields.
- 2026-10-10: Animation tracks reference registry float, vec3, and color fields; keys use seconds and optional linear, ease-in-out, or step interpolation (linear is the default). Scrubbing evaluates the saved scene without mutating it.
- 2026-10-11: Keys also accept `ease-<in|out|in-out>-<family>` names and `bezier` with `[x1, y1, x2, y2]` points (x in 0..1, y in -2..3); `ease-in-out` keeps its original smoothstep curve. Overshooting values are clamped to each field's range during evaluation, so Back, Elastic, and bezier curves never fail validation.
- 2026-10-11: Animation presets are pure functions that build tracks from the object's current values and apply as one undoable Animator update; they replace tracks for the same property and adopt their own length and looping only when they are the object's sole animation.
- 2026-10-10: During Play, scripts read the latest physics-synchronized scene, collision handler edits apply after physics sync, and animation applies last each rendered frame; Stop still restores the pre-play snapshot.
- 2026-10-10: Entity reparenting uses an optional `parent` field on update operations so hierarchy drag-and-drop stays validated, atomic, and undoable through `applyOps`.
- 2026-10-10: The physics world uses the scene's fixed timestep and a built-in static ground collider at y=0; Play owns a scene snapshot and Stop restores it exactly.
- 2026-10-10: Script source compiles from checked AST nodes into a restricted context API; generated code does not embed user source. Script mutations use `applyOps`, and `random()` uses an LCG reset to seed 1 on Play.
- 2026-10-10: Browser AI requests go through a Vite dev-server middleware that reads `AI_API_KEY`, `AI_MODEL`, and optional `AI_BASE_URL` from server environment/config; the browser never receives the key, and no `VITE_`-prefixed secret is used.
- 2026-10-14: The scene assistant's creation contract gives current user style priority, then existing scene continuity and recent successful requests, then a cohesive stylized default. The contract covers recognizable silhouettes, material roles, spacing, camera composition and useful named folders. Recent request context is capped at six requests of 2,000 characters each and resets on document replacement.
- 2026-10-14: Large scene context is capped at 23,000 characters, prioritizing selection, requested subjects, their ancestors, and root assemblies. Snapshots disclose omitted objects/details and use explicit parent ids rather than assuming parent order. Prior-request context has an additional 6,000-character serialized budget, keeping the most recent requests when it fills. Model responses are capped at 36,000 characters, with a smaller budget for long requests; reviewer scene space adapts to the operation plan and measured feedback. Rejected response text and correction feedback are bounded independently to fit the existing transport limits. All script issues remain available to local validation even when reviewer context samples them. A regression builds 1,407 objects from compact assembly/repeat instructions and verifies review messages fit the transport limits. New/Open/provider changes rotate the cache instance so pending calls cannot refill a cleared document/provider cache.
- 2026-10-14: Three high-level scene tools (`assemble`, `repeat`, `group`) compile to ordinary operations, sharing atomic scene validation and one inverse batch. Repetition copies full subtrees in parent-first order, remaps component entity references and deactivates copied cameras. Script text remains unchanged; relative script targets are required for reusable behaviors. Assemblies require unique ids, preventing ambiguous references when a source is repeated. Tool expansion is capped at 1,500 operations before expensive validation/runtime checks.
- 2026-10-14: A deterministic quality report is supplied to the independent model review and displayed in the Assistant. It checks hierarchy-aware world bounds, missing surfaces, identical geometry/poses, collapsed transforms, floor penetration, possible dynamic overlaps, flat object lists, and static camera framing. It uses the same camera configuration as the runtime. Bounds and design warnings are advisory because intent, tracking cameras, viewport aspect ratio and actual contact geometry can change their interpretation. The system makes no claim of visual or Rapier verification. Explicit positions are preserved rather than silently repaired. Baseline compile/runtime issues are separated from introduced errors; runtime issue identities are retained before filtering so long baseline issue lists cannot hide new failures.
- 2026-10-14: Stable instructions and schemas precede mutable scene text for provider prefix caching. Local caches are bounded LRU caches with a five-minute TTL and defensive cloning: two static-prefix entries, six scene descriptions, twelve reviewed builds. Content keys detect in-place scene changes; reviewed-build keys include the full scene, request, style context, instructions and schema. Cache hits reapply operations and repeat script compilation, isolated runtime and geometry checks. Rejected builds and first-draft fallbacks never enter the result cache. Scene/provider changes clear the editor result cache; no prompts/scenes are persisted by these caches. Review input retains compact high-level build operations so arrays need not be regenerated part by part.
- 2026-10-24: AI calls name a task and the server picks the model. Parse and scene drafts use gpt-6-luna. Scene reviews use gpt-6-sol only behind `AI_SOL_ENABLED`, and only when the draft creates 3+ objects or needed a correction. Clean drafts that don't qualify skip review. Draft retries are capped at 2 and review retries at 1. Credits are priced from provider token usage at $0.00167 each. The site has a $150 monthly budget spread over the remaining days, with a $15 daily ceiling. The system prompt is byte-identical across scene calls (scene, history and reviewer instructions moved to the user message) so provider prefix caching applies, and a stable `prompt_cache_key` is sent per task. The gpt-6-sol cached-input price ($0.20/M) comes from third-party listings and should be checked against the provider's pricing page.
- 2026-10-25: `Mesh.radiusTop` is an optional schema field. It stays unset unless chosen, is never stripped as a default (applyOps and save both keep it), and readers derive the real top from the shape: radius for a cylinder, 0 for a cone. A plain default of `radius` would have turned every existing cone into a cylinder. Wedge, truncated-shape and mirrored colliders use a convex hull of the same geometry the viewport draws.
- 2026-10-25: Shape variety comes from fields on existing shapes (`bevel`, `sides`, `arc`, `hollow`), not new shape names; only `torus` and `text` are new shapes. Faceted cylinders/cones (12 sides or fewer) measure `radius` to the faces, so a 4-sided pyramid of radius r matches a box of radius r. Concave shapes use a triangle-mesh collider only when the body never moves on its own; dynamic ones use the convex hull, because Rapier triangle meshes have no volume for dynamic contact. Text uses Droid Sans Bold (Apache-2.0) bundled as a 43 KB ASCII subset, because three.js no longer ships fonts in its npm package and exports must work offline.
- 2026-10-25: Visual critique (behind `AI_CRITIQUE_ENABLED`, off by default) renders the finished build in the browser with its own offscreen WebGLRenderer from the export scene graph (`createThreeScene`), so the live viewport and its gizmos are never involved: a 3/4 view and an orthographic top-down view, 512 px JPEG at quality 0.7. Only `scene_critique` may carry images, inline data URLs only (never URLs the provider would fetch), at most 2 of 300 KB. It runs after the review on builds that created 3+ entities, and only when the visitor holds the worst case of the critique plus its fix pass (23 + 5 credits). Below 8/10, one fix pass (Luna) returns ops applied on top of the build; it is kept only if it applies, adds no script errors and no more geometry flags. There is never a second critique. If any texture fails or is slow (3 s), the renders use plain material colors, because an unloaded texture draws black.
- 2026-10-25: A follow-up build sees the scene as an outline, not in full: loose top-level objects in full, and every group collapsed to one line with its world bounding box, center x/z, y range and its own Transform. Only the groups the request involves are listed part by part; a nested group opens its ancestors one level, so its siblings stay collapsed. A reference step (`scene_context`, on Sol behind `AI_SOL_ENABLED`) chooses those groups from an outline that also names each group's parts. It also resolves pronouns and vague references to ids, restates the request, and lists spatial facts read from the outline. The player's own words stay the request; the resolution is context before it. When the step is off, skipped for credits or fails, the selection and the entities the request names are expanded instead. A selected part inside a group is always expanded so it can be edited by id. The first build on an empty scene skips the step. The review and the critique's fix pass see the same outline plus everything the build created or changed. Free floor spots now avoid parts inside groups, not just loose objects.
- 2026-10-11: Standalone HTML inlines a build-time esbuild bundle of the same Three.js and shared simulation/runtime modules used by the editor; this keeps exports offline-capable at the cost of a multi-megabyte file.
- 2026-10-11: WebM export uses MediaRecorder on the live Play canvas at 30 fps and selected output dimensions; it records in real time rather than running an offline deterministic frame renderer.
- 2026-10-10: Svelte 5, three.js, Rapier, Vite, TypeScript, and Vitest are the required app stack from `app-build-prompt.md`; no other app runtime dependency is added in M1.

The assistant changes above draw on [Anthropic's effective-agent workflow guidance](https://www.anthropic.com/engineering/building-effective-agents), [tool design and outcome evaluation guidance](https://www.anthropic.com/engineering/writing-tools-for-agents), [context engineering guidance](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [prompt prefix caching documentation](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), and [Three.js object hierarchy/world-transform documentation](https://threejs.org/docs/pages/Object3D.html), reviewed on 2026-10-14. The particular design defaults, budgets, and advisory checks are project decisions, rather than measured guarantees of model output quality.

For live-provider quality evaluation, compare builds from the same original scene and model using requests for a cozy oak/sage reading corner, a bright low-poly playground, a precise row of five industrial lamps, a deliberately asymmetric neon sculpture, a submerged structure, and a small edit preserving an existing room's style. Inspect required parts/counts, requested colors/materials, world-space support/clearance, folder names, camera composition, runtime issues and remaining warnings; record model calls and latency. Render and run Play for the visual/physics criteria. Automated regression tests exercise tool expansion, atomic undo, reference remapping, world transforms, diagnostics, style context, retry feedback and cache behavior with deterministic completions; they do not establish a live-model visual quality score.
